# Личные финансы

Google Таблица хранит операции и рассчитывает отчёты. Apps Script принимает запросы с токеном. Статическое приложение разбирает выписки на устройстве и работает на GitHub Pages. Для работы не нужны платные сервисы.

## 1. Создать Google Таблицу

1. Создайте пустую Google Таблицу в аккаунте, которому будет принадлежать приложение.
2. В таблице откройте **Расширения → Apps Script**. Создайте файлы скрипта, соответствующие файлам `apps-script/*.gs`, и скопируйте их содержимое.
3. В **Настройках проекта** включите показ файла манифеста и скопируйте содержимое `apps-script/appsscript.json`. Сохраните проект.
4. В списке функций выберите `setupFinance`, нажмите **Выполнить** и предоставьте разрешения на работу с таблицей. Скрипт создаёт листы, начальный справочник, формулы, проверки данных, оформление и токен. Локаль таблицы устанавливается в `en_US` для синтаксиса формул. Даты отображаются в формате `дд.мм.гггг`, часовой пояс — Москва.
5. В таблице откройте **Вид → Скрытые листы → Настройки** и скопируйте значение рядом с `token`. Держите таблицу и токен в закрытом доступе. Чтобы заменить токен, обновите значение в таблице и переподключите приложение на каждом устройстве.

| Лист | Содержание |
|---|---|
| Транзакции | ID, дата, описание, положительная сумма, категория, подкатегория, тип. |
| Справочник и Правила | Подкатегории, ключевые слова через `|`, виды учёта, пользовательские фрагменты описаний и приоритеты. |
| Бюджет | Слева настройка года, квартала и месяца внутри квартала, в строке 12 начинается годовая матрица. Справа — формульный план и факт по подкатегориям. |
| Дашборд | Настройки периода в столбце B, KPI в D, годовые таблицы категорий с долями и полосами, сводка кредитов ниже. |
| Кредиты | Условия кредитов, статус и атрибуты кредитных карт. |
| График платежей | Даты, плановый платёж, разбивка, досрочное погашение, остаток, фактическая сумма и статус. |
| Досрочные погашения, Привязки, Без привязки | События пересчёта, связи операций с кредитами и список операций для проверки. |
| Учёт, Настройки, Синхронизация | Формульная классификация сумм, параметры проекта, метаданные отправленных изменений. |

Формулы создаются в `Setup.gs`, `Reports.gs` и `Loans.gs`. `Учёт` нормализует доходы, расходы и кредитные суммы для `SUMIFS` и `QUERY`. График использует формулы платежа, процентов и остатков. Просроченные платежи выделяются статусом по дате. При редактировании условий существующего кредита в таблице обработчик `onEdit` перестраивает график. Новые кредиты, досрочные погашения и привязки удобнее создавать через сайт, где проверяются обязательные поля и выдаются ID.

## 2. Развернуть Apps Script

1. Нажмите **Начать развёртывание → Новое развёртывание**. В выборе типа укажите **Веб-приложение**.
2. В поле «Выполнять от имени» выберите себя. В поле «У кого есть доступ» выберите **Все**, затем нажмите **Развернуть** и подтвердите разрешения.
3. Скопируйте URL, который заканчивается на `/exec`. URL `/dev` предназначен для редакторов скрипта.
4. Проверьте URL в браузере. Открытие без токена должно вернуть JSON с кодом `UNAUTHORIZED`. Если аккаунт Google Workspace запрещает доступ «Все», потребуется аккаунт с разрешённым анонимным развёртыванием.
5. Для обновления кода откройте **Начать развёртывание → Управление развёртываниями → Изменить** и выберите новую версию.

Запросы сайта используют `POST` с `Content-Type: text/plain;charset=UTF-8` и JSON `{ "token": "...", "action": "connection.check", "data": {} }`. Apps Script возвращает JSON с `ok` и `data` или `ok: false` и `error.code`. Тело простого запроса позволяет использовать стандартный кросс-доменный ответ Apps Script через Google. Приёмка включает реальный браузерный запрос с опубликованного домена Pages. Отдельный прокси не нужен.

| Методы | Основные поля `data` |
|---|---|
| `connection.check`, `backup.get` | Без аргументов. Резервная выгрузка включает всю историю. |
| `sync.pull`, `transactions.list`, `dashboard.get` | `from`, `to` в ISO, `year`, `month`; для синхронизации опционально `budget: {year, month}`. |
| `import.preview`, `import.commit` | `transactions: [{date, description, amount, type, directoryId, bank?, bankId?}]`, опционально `rules`. |
| `transactions.updateCategory` | `id`, `directoryId`, опционально `rule: {pattern}`. |
| `directory.list`, `directory.save`, `directory.delete` | Список без полей. Запись использует `id?`, `category`, `subcategory`, `keywords`, `kind`; удаление — `id`. |
| `rules.list`, `rules.save` | Список без полей. Запись использует `id?`, `pattern`, `directoryId`, `priority`, `active`. |
| `budget.get`, `budget.savePlan` | `year`, `month`; запись также принимает `directoryId`, `amount`. |
| `loans.list`, `loans.save`, `loans.schedule` | Список без аргументов; график принимает `id`. Запись использует параметры из формы кредита. |
| `loans.previewPrepayment`, `loans.recordPrepayment` | `loanId`, `date`, `amount`, `type`, `mode`, опционально `transactionId` при записи. |
| `loans.linkTransaction` | `loanId`, `transactionId` и `paymentId` либо `kind` для операции без строки графика. |

В ответе запроса импорта `added`, `duplicates`, `uncategorized` и `matched` — счётчики. Скрипт повторно проверяет дубли под блокировкой и пишет новые транзакции одним `setValues`. Ошибки валидации включают `INVALID_DATE`, `INVALID_CATEGORY`, `INVALID_LOAN`, `INVALID_LINK`. Для коллизии блокировки возвращается `BUSY`. Метаданные офлайн-правок идут в объекте `change: {id, key, at, base}` верхнего уровня.

## 3. Опубликовать сайт

1. Поместите проект в репозиторий GitHub с основной веткой `main`. В **Settings → Pages → Build and deployment** выберите **GitHub Actions**.
2. После загрузки файлов в `main` workflow `.github/workflows/pages.yml` публикует только каталог `site/`. Если Source настроили позже, вручную запустите workflow во вкладке **Actions**.
3. По адресу из **Settings → Pages** введите URL веб-приложения и токен. Нажмите **Проверить и подключить**. Параметры хранятся локально в IndexedDB. Если токен сменился, укажите новый в настройках приложения.
4. На iPhone откройте сайт в Safari, нажмите **Поделиться → На экран «Домой»**, затем запустите приложение с иконки. После первой загрузки оболочки и синхронизации откройте его в авиарежиме.
5. Сайт принимает CSV, XLSX и текстовый PDF Альфа-Банка. На iPhone выберите документ через «Файлы». Просмотрите строки и статистику, проверьте категории и нажмите **Подтвердить импорт**.

Изменения в офлайне отправляются при подключении или обновлении страницы. До синхронизации сводки отражают последний сохранённый снимок. При конфликте между изменениями API сравнивает время правки, при совпадении использует ID изменения. Для сравнения правок между устройствами желательно включить автоматическую настройку часов. Офлайн-предпросмотр показывает оценку по последним сохранённым данным. Дубли и совпадения с платежами перепроверяются при синхронизации. Для полного экспорта XLSX/JSON подключитесь к сети. Экспорт офлайн содержит доступный на устройстве снимок.

GitHub Pages обслуживает только статические файлы. PapaParse, SheetJS и PDF.js включены в `site/vendor/` с лицензиями, отдельного CDN при работе приложения нет. При следующем выпуске обновляйте номер оболочки в `site/sw.js`. Service Worker сам заменит старый кэш после загрузки полной оболочки.

## Категории и новые банки

- В **Загрузка → Категории и правила** добавьте категорию и подкатегорию или редактируйте существующую. Удаление из выбора оставляет прежние операции читаемыми. Переименование через сайт обновляет исторические операции и план бюджета.
- Ключевые слова в справочнике разделяются символом `|`. Правило использует подстроку описания. Чем больше приоритет, тем раньше применяется правило. Для переводов конкретному человеку укажите имя как фрагмент и назначьте подкатегорию. Формулировки для переводов между собственными счетами и округлений можно расширять через справочник.
- В предпросмотре можно заменить категорию, указать фрагмент в поле правила или снять флажок. Порядок применения — ручной выбор, правила пользователя, справочник. Колонки банковских категорий игнорируются.
- Для другого банка добавьте заголовки или отдельный адаптер в `site/js/parsers/`. Передайте нормализованному парсеру строки либо объект с датой ISO, описанием, суммой в рублях и типом. Добавляйте `bankId` только для постоянного идентификатора операции. Порядковый номер в документах Альфа-Банка меняется между выписками. Если постоянного ID нет, используется SHA-256 даты, подписанной суммы и нормализованного описания. Одинаковые операции с этими тремя полями схлопнутся. При импорте одного периода из разных форматов проверьте, совпадают ли описания и присутствие ID.
- Текстовый PDF использует координаты колонок «Операция», «Расход», «Приход» и «Назначение платежа». В PDF-назначениях длинные цифровые реквизиты удаляются. Для сканов, банковских справок с другой вёрсткой и валютных операций используйте поддерживаемую выгрузку в рублях. Частные документы оставляйте вне публичного репозитория.

## Кредиты

Первый платёж ставится на заданный день следующего календарного месяца, с переносом на последний день короткого месяца. Ставка делится на 12, проценты округляются до копеек каждый месяц. При совпадении дат сначала рассчитывается очередной платёж, затем досрочный. При полном погашении в середине месяца модель использует остаток после последнего очередного платежа. Фактическую сумму закрытия, дневные проценты и условия конкретного банка сверяйте по банковскому графику. По кредитной карте введите текущий долг, лимит, льготный период и минимальный платёж вручную.

Списание с однозначным совпадением даты в пределах трёх дней и суммы с точностью до копейки получает автоматическую привязку. Слова из карточки кредита помогают выбрать один из нескольких графиков. В **Транзакции → Привязать** можно выбрать платёж вручную, в том числе при отклонении суммы, или отнести платёж к процентам, комиссиям или телу кредита. Досрочный платёж, отмеченный в калькуляторе, меняет график. Прошедшее досрочное погашение считается учтённым в остатке, а привязка выписки отображает его в истории. Выдача кредита, тело долга, свои переводы и накопления выделяются отдельными видами учёта. Проценты и комиссии входят в расходы.

## Приёмка

**Демо.** Создайте кредит «Банк Пример» с датой выдачи 31.10.2026, суммой 1 000 000 ₽, ставкой 18%, сроком 36 месяцев, аннуитетом, днём платежа 15 и словами `банк пример`. До импорта или после него зарегистрируйте частичное досрочное погашение на 50 000 ₽ с датой 18.11.2026. Импортируйте `fixtures/alfa-demo.csv` и выберите ноябрь 2026 в фильтрах. Если выписка уже импортирована, приложение проверит её на совпадение с добавленной строкой графика. При расхождении можно выбрать платёж вручную.

- [ ] С iPhone выбрать CSV/XLSX из «Файлов», подтвердить импорт. Операции видны в Google Таблице.
- [ ] При повторной загрузке 25 строк демо — 0 новых операций и 25 дубликатов.
- [ ] Запрос без токена получает `UNAUTHORIZED`.
- [ ] Изменение категории на сайте отражается в таблице и в сводке.
- [ ] Первый платёж демо-кредита равен 36 152,40 ₽. У обычного графика 36 платежей, конечный остаток 0 ₽.
- [ ] Списание на 36 152,40 ₽ за 15.11.2026 отмечает платёж оплаченным. Тело — 21 152,40 ₽, проценты — 15 000 ₽.
- [ ] Частичное и полное досрочное погашение пересчитывают остаток и график. Сравнить оба режима частичного погашения.
- [ ] Выдача кредита и тело платежа не входят в обычные доходы и расходы. Проценты входят в расходы.
- [ ] На ширине 375–430 px работает горизонтальная прокрутка таблиц, нижняя навигация учитывает safe area.
- [ ] Safari добавляет приложение на экран «Домой». Оно запускается без адресной строки и открывает последний снимок без сети. Правка офлайн синхронизируется после подключения.
- [ ] На опубликованном HTTPS-сайте проверить installability через **Chrome DevTools → Application → Manifest**. В актуальном Lighthouse отдельная категория PWA снята с поддержки, поэтому проверить manifest, service worker и офлайн-запуск отдельно.

### Локальные проверки

- `node tests/core.mjs` проверяет CSV/XLSX, приоритет правил, ответ без токена, дедупликацию, кредитное сопоставление и расчёт вариантов графика. Тест модели использует заглушки API Google.
- `node tests/check-private-pdf.mjs "/путь/к/файлу.pdf"` проверяет текстовый PDF в Node.js и выводит только количество страниц и строк. PDF в репозиторий не входит.
- Для локального просмотра запустите `python3 -m http.server 8000 --directory site`. Реальная таблица и кросс-доменный запрос требуют развёрнутого Apps Script.
